# Inhibitor Logs

## Dataset Description

This dataset contains the **execution logs generated during the AI Safety Inhibitor Drift Audit stress test**.

The logs record the internal events produced by the inhibitor while processing requests during the audit. Each request represents a conversation or reasoning chain that was evaluated by the inhibitor.

The dataset provides a detailed view of the **internal processing pipeline**, including embedding generation, reasoning steps, rule evaluation, and final validation events.

---

## Log File

`inhibitor_logs_set_a.csv`

This file contains the raw event logs produced during the drift audit runs.

Each row represents **one internal event** generated by the inhibitor while handling a request.

---

## Log Schema

The CSV file contains the following columns.

| Column | Description |
|------|-------------|
| timestamp | Timestamp indicating when the event occurred |
| apiKey | Identifier associated with the request source |
| event | Type of internal event recorded by the inhibitor |
| meta | JSON metadata containing contextual information about the event |

The `meta` column contains structured JSON data describing additional details related to the event. Depending on the event type, it may include information such as rule identifiers, validation details, reasoning outputs, or request context.

---

## Event Lifecycle

Each inhibitor request produces a sequence of internal events that reflect the processing pipeline.

A typical request lifecycle may include events such as:

```
embedding_start
embedding_complete
llm_prompt_start
llm_prompt_complete
inhibition_observation_description_response
inhibition_prediction_reason_response
rules_inhibition_rule_start
rules_inhibition_rule_passed
rules_inhibition_complete
inhibition_final_validation
request_success
```

These events represent the progression of a request through the
inhibitor system, from initial processing to final validation.

Because multiple internal operations occur for each request, the number
of log events is significantly larger than the number of requests
processed.

---

## Event Categories

The logs contain several categories of events corresponding to different
stages of the inhibitor pipeline.

### Embedding Generation

These events correspond to the creation of vector embeddings used for
semantic matching.

```
embedding_start\
embedding_complete
```

---

### LLM Reasoning Steps

These events represent internal prompt executions used to interpret the
conversation context.

```
llm_prompt_start\
llm_prompt_complete
```

---

### Observation and Reasoning Outputs

These events record internal descriptions and reasoning related to
detected risk signals.

```
inhibition_observation_description_response\
inhibition_prediction_reason_response
```

---

### Rule Evaluation

These events occur when the inhibitor evaluates candidate rules from the
knowledge base.

```
rules_inhibition_rule_start\
rules_inhibition_rule_passed\
rules_inhibition_rule_binding_missing\
rules_extraction_value_missing
```

---

### Pipeline Completion

These events indicate the final stages of request processing.

```
rules_inhibition_complete\
inhibition_final_validation\
request_success
```

---

## Notes

-   Each row represents a **single event in the inhibitor processing
    pipeline**.
-   Multiple events correspond to a single request evaluation.
-   The `meta` column contains additional event-specific information
    encoded as JSON.

These logs provide a detailed trace of how the inhibitor processes
requests and records the sequence of internal operations performed
during evaluation.
