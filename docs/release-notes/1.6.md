# Inhibitor Service 1.6 Release Notes

## Overview

Version 1.6 moves the Philly Codefest OpenBuild from repository enablement into active event execution. This release aligns challenge naming with the final event framing, simplifies participant instructions, clarifies how teams can submit Inhibitor-enabled agents and externally hosted systems, refreshes shared dashboard log assets, and folds Codefest participant submissions into the repository's team-workspace structure. The result is a cleaner handoff between event operations, judging, and post-event review.

## Highlights

- Realigned Codefest challenge structure and navigation around the final challenge set: Trust Accelerator Campaign (Digital Awareness), Inhibitor Innovation & Red Team Gauntlet, and Glass Box Dashboard.
- Simplified challenge language and scoring guidance so teams and judges can work from clearer, challenge-specific briefs instead of relying on broader event wording.
- Strengthened Challenge 2 submission guidance to support both net-new agent builds and existing or externally hosted agent integrations, with clearer expectations for reproducibility, evidence, and Inhibitor-specific analysis.
- Added practical agent-development guidance that emphasizes ROA-oriented workflows, performance-mode defaults, and direct remediation behavior during Codefest builds and evaluations.
- Refreshed Challenge 3 shared sample log assets so dashboard and audit experiences can be evaluated against updated baseline datasets during the event.
- Added and populated Codefest team workspace folders, then merged Codefest participant submissions and related pull requests into those workspaces as part of the event merge window, without enumerating individual team code changes in these notes.
- Continued tightening the shared Codefest operating model across `codefest/README.md`, `codefest/TEAM_MANAGEMENT.md`, and `codefest/team-workspaces/README.md` so staff onboarding, submission packaging, attribution, and final review stay consistent.

## Adoption Guidance

- Start with `codefest/README.md` to align on the final challenge framing, scoring model, and team-workspace flow.
- Use `codefest/TEAM_MANAGEMENT.md` and `codefest/team-workspaces/README.md` as the operational baseline for staff setup, submission packaging, attribution, and merge-window review.
- For challenge execution, route teams directly to the updated challenge brief that matches their workstream, especially `codefest/challenge-2-inhibitor-innovation-red-team/README.md` when they are extending an existing agent rather than building from scratch.
- Use the refreshed Challenge 3 sample logs as the common baseline for dashboard demos and audit UX comparisons.
- Treat Codefest participant workspace merges as event integration artifacts; evaluate them at the team-folder level rather than as canonical product examples until post-event curation is complete.

## Looking Ahead

- Curate the strongest Codefest submissions into reusable first-class examples, notebooks, or case-study artifacts after event review.
- Add lightweight validation or packaging checks for workspace submissions so README quality, attribution, and reproducibility can be reviewed faster.
- Separate long-lived reference materials from event-specific workspace artifacts where needed to keep the repository easy to navigate after Codefest.
- Consider a post-Codefest summary release or showcase note that highlights promoted outcomes without coupling them to every merge-window commit.
