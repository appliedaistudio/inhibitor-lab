# Inhibitor Service 1.9 Release Notes

## Overview

Version 1.9 extends inhibitor-lab’s notebook-first integration flow into a focused high-risk policy validation workflow. This release introduces and then hardens a dedicated self-harm realtime safety test notebook, giving teams a concrete way to pressure-test self-harm and suicide response behavior with the same live-loop structure used in the repository’s baseline realtime moderation example. The result is a more operational bridge between general agent moderation patterns and policy-specific debugging, inspection, and remediation for one of the most sensitive deployment domains.

## Highlights

- Added `notebooks/self_harm_policy_realtime_test_agent.ipynb`, a dedicated notebook for testing self-harm and suicide policy behavior with a real-time assistant loop and Inhibitor checks.
- Kept the notebook aligned with the repository’s broader notebook idiom by explicitly following the runtime pattern used in `realtime_moderation_agent.ipynb`, while narrowing the scenario set to direct intent, implied intent, method-seeking, imminence, and safe-support contexts.
- Refined notebook terminology and case naming so safe third-party assistance and informational contexts are treated as nuanced non-violation scenarios rather than generic “guardrails,” reducing ambiguity around false-positive-resistant evaluation.
- Expanded insight-mode visibility during iterative remediation, first with iteration-level debugging counts and then with full Inhibitor API response printing for deeper audit and tuning workflows.
- Updated the notebook to parse the newer `/check` response structure more deliberately, separating `llm_inhibition` from `rules_inhibition`, distinguishing policy rule violations from rule runtime errors, and surfacing structured debug summaries for both paths.
- Smoothed notebook execution in Colab and keyed environments by reading secrets with environment fallback and aligning the workflow with the self-harm policy attached to the API key.
- The current notebook state includes a five-case policy-focused test matrix and a sample run showing `Passed 5/5 policy-focused test cases.`

## Adoption Guidance

- Start with `../../notebooks/self_harm_policy_realtime_test_agent.ipynb` when validating assistant behavior in self-harm, suicide, or acute-risk support scenarios.
- Use this notebook in `insight` mode during policy authoring and debugging so you can inspect both semantic predictions and deterministic rule outputs before simplifying the loop for lower-latency environments.
- Treat the structured debug helpers as part of the value of this release: they help distinguish true policy failures from rule-shape or runtime issues, which is especially important when tuning sensitive-domain policies.
- Keep the baseline `../../notebooks/realtime_moderation_agent.ipynb` nearby as the generic realtime pattern, then use the self-harm notebook as the specialized high-risk variant.
- Make sure the API key you use is attached to the intended policy set before interpreting notebook results; this release assumes policy selection happens through the key context rather than ad hoc notebook-side switching.
- Pair notebook runs with `../inhibitor-api.md` so `/check` request/response shapes, operating modes, and log/review behavior stay aligned with the live API contract.

## Looking Ahead

- Factor shared realtime-loop helpers between the base moderation notebook and the self-harm notebook so mode handling, repair logic, and diagnostics do not drift.
- Add lightweight expected-response fixtures or snapshots for sensitive-domain notebooks to make regression review easier as the API envelope evolves.
- Surface the self-harm notebook more prominently in repository navigation so specialized safety validation flows are easier to discover from the root onboarding path.
- Extend policy-specific notebook coverage into adjacent high-risk domains while preserving the same inspectable ROA-style remediation loop.
