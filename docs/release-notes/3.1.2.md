# Inhibitor Service 3.1.2 Release Notes

## Overview

This `inhibitor-lab` release aligns the repository with Inhibitor Service 3.1.2 and adds two evaluation notebooks plus two application-guidance papers. Together, these resources move beyond screening a single prompt: they show how a host application can evaluate retrieved content, distinguish legitimate personal-information use from misuse, place checks at consequential boundaries, and enforce deterministic outcomes.

The notebooks are evaluation tools, not universal performance claims. Their results depend on the active service, rules, configuration, and test corpus. The application remains responsible for trusted context, identity and authorization, decision mapping, side-effect control, and safe handling of errors or indeterminate results.

## Highlights

### Indirect injection boundary evaluation

- Added the [Indirect Injection Boundary Matrix](../../notebooks/indirect_injection_boundary_matrix.ipynb) for testing attacks hidden in web pages, RAG documents, and other content an agent reads.
- Separates caller speech, retrieved chunks, web content, and application policy so untrusted text cannot declare itself trusted.
- Declares a synthetic corpus and expected outcomes before execution, then reports detections, misses, false alarms, errors, latency, and confusion matrices.
- Demonstrates an application-owned quarantine decision and mock tool gate, with uncertain or failed checks treated as indeterminate rather than safe.
- Includes optional, disabled-by-default DILL rule generation and a bounded Insight-mode diagnostic path for investigating mismatches.

### Legitimate-use PII evaluation

- Added the [Legitimate-Use PII Evaluation](../../notebooks/legitimate_use_pii_evaluation.ipynb) to test whether closely paired cases distinguish permitted personal-information use from misuse.
- Keeps built-in evidence, reviewed DILL evidence, planned contextual behavior, and future enhanced evidence explicitly separate.
- Uses application-supplied facts such as verification, consent, purpose, relationship, destination, and data minimization instead of trusting claims embedded in candidate text.
- Measures legitimate false blocks, unsafe misses, indeterminate results, pairwise consistency, latency, and gaps against predeclared observation families.
- Uses synthetic placeholders and exports regression artifacts without raw context envelopes, transcripts, contact lists, or customer data.

### Real-time application practices

- Added [Using the Inhibitor in Real-Time Applications](../real-time-application-best-practices.md), a practical guide to placing checks at clear trust boundaries while keeping latency and failure behavior predictable.
- Covers bounded context, application-owned enforcement, deadlines and fallback actions, limited correction loops, parallel independent work, sensitive-data minimization, joint speed-and-safety measurement, and staged rollout.
- Provides a voice-agent reference flow and launch checklist that teams can adapt to other interactive systems.

### Beyond prompt screening

- Added [Beyond Prompt Screening: Broader Uses for Inhibitor](../beyond-prompt-screening.md), which extends the integration model to tool actions, database writes, outbound responses, audit trails, multi-step attacks, human review, and multilingual testing.
- Clarifies the division of responsibility: Inhibitor supplies policy evidence, while the host application owns authentication, authorization, schemas, side effects, recovery, and review workflows.
- Recommends stable rule IDs and deterministic application actions instead of using free-form explanations as executable instructions.

## Adoption Guidance

1. Begin with the [real-time application guide](../real-time-application-best-practices.md) to identify trust boundaries, latency budgets, fallback behavior, and rollout stages.
2. Use [Beyond Prompt Screening](../beyond-prompt-screening.md) to prioritize checks around actions that are difficult to reverse, including tool calls, writes, and disclosures.
3. Run the [indirect injection matrix](../../notebooks/indirect_injection_boundary_matrix.ipynb) with synthetic content to calibrate quarantine behavior for each content source.
4. Run the [legitimate-use PII evaluation](../../notebooks/legitimate_use_pii_evaluation.ipynb) to measure both misuse detection and unnecessary blocking across paired contexts.
5. Review any generated DILL policy before activation, map stable findings to deterministic application actions, and fail safely on timeouts, malformed responses, missing trusted facts, and selector failures.
6. Establish application-specific acceptance criteria and rerun the evaluations when the service version, policy set, model, input pipeline, or decision mapping changes.

## Interpretation Boundaries

- A passing check means the configured evaluation found no reason to block; it does not make content trusted or authorize an action.
- The notebooks do not establish production-wide accuracy, language coverage, compliance, or safe autonomous operation.
- Mock tools and synthetic records do not validate real downstream authorization, database, rollback, or incident-response controls.
- Optional DILL generation can change a shared ruleset and must remain disabled unless an authorized operator deliberately enables and reviews it.
- Planned observation families in the PII notebook are targets until a deployment returns corresponding stable evidence.
