# Inhibitor Service 1.3 Release Notes

## Overview

Version 1.3 introduces a full Codefest enablement track in the repository. This release adds a structured event workspace, challenge playbooks, starter agent assets, and staff/team operating guidance so multiple teams can build, test, and submit Inhibitor-focused projects in one coordinated workflow.

## Highlights

- Added a new `codefest/` event hub with a central challenge index, shared scoring rubric, and support model for event execution.
- Added challenge-specific documentation for Policy-to-Code, Red Team Gauntlet, and Glass Box Dashboard, each with mission scope, workflow steps, submission requirements, and scoring criteria.
- Added starter agent notebooks for Challenge 1 (policy-to-code) and Challenge 2 (red-team) to accelerate team onboarding and hands-on experimentation.
- Added a `TEAM_MANAGEMENT.md` operations guide for staff, covering team setup, merge-window flow, support responsibilities, and fairness policy.
- Added team workspace guidance and a reusable `team-template/README.md` so teams can submit with consistent run instructions, assumptions, and MIT-compatible attribution.
- Added fixed sample log datasets for Challenge 3 so dashboard and audit UX outputs can be compared against a common baseline.

## Adoption Guidance

- Start in `codefest/README.md` to align all teams on challenge goals, rubric expectations, and support channels.
- Use `codefest/TEAM_MANAGEMENT.md` as the event runbook before kickoff to standardize folder creation, API key readiness, and merge-window logistics.
- Point teams to the challenge README that matches their focus area, then use the starter notebooks when they need a fast path to agent-based prototypes.
- Require each team to stage work in `codefest/team-workspaces/<team-name>/` with a complete README, reproducible steps, and attribution details before final merge.
- Keep Challenge 3 sample logs read-only so final dashboards remain comparable across teams.

## Looking Ahead

- Add post-event packaging guidance so winning team solutions can be promoted into reusable repository examples.
- Expand starter kits with automated validation checks for submission completeness and reproducibility.
- Add optional scoring worksheet templates to streamline judge review and cross-team comparison.
